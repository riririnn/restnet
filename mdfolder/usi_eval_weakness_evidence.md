# restnetの対外エンジン評価: 「弱さは実力であってバグではない」ことの証拠

（2026-07-27。restnet vs やねうら王(水匠5/Elmo) の評価で、restnetが0/20で
負けた原因が「バグか実力か」を切り分けた記録。）

## 観測された事象

- restnet iter 60000（最強モデル）を、やねうら王＋水匠5 および ＋Elmo と
  1手1秒で対戦させたところ、**水匠5に0/20、Elmoに0/20**（全敗）
- 敗着までの手数が短い（投了あり: 14〜35手 / 投了なし: 27〜30手）
- 疑問: 「実力差があってもこんなに早く終わるのは異常では?」→ バグを疑い調査

## 結論（先に明記）

**バグではなく、restnetの絶対棋力が低いことが原因。** 調査の過程で座標系と
着手選択の2つの実バグを発見・修正したが、それらを直した後もrestnetは正常に
思考した上で（1秒で777シミュレーション、妥当な手を選択）トップエンジンに
力負けしている。自己対局Elo（+2666単調増加）が示すのは「学習したこと」で
あって「絶対的に強いこと」ではない。標準将棋は巨大で、60万局・6ブロックの
小型ネットでは、超人的な水匠5/Elmoには遠く及ばない（計算資源から見て想定内）。

## 調査で実際に見つかり修正した「本物のバグ」

| # | バグ | 症状 | 修正 |
|---|---|---|---|
| 1 | 座標系の左右反転 | restnetの手をUSIに変換するとき筋が反転。やねうら王が「角が横に動く」等の非合法手を拒否して即クラッシュ | shogi_coords を C++ convertAZ と一致する標準座標(col=file-1)に修正 |
| 2 | 終局(PASS)の未処理 | 詰み局面でminizeroが返す "PASS" をusi_bridgeが無視し、古い手を誤変換して非合法手を送信 | genmoveの"PASS"→終局として final_score で裁定 |
| 3 | 着手が確率サンプリング | 評価時に温度1のsoftmaxサンプリングで、restnetがわざと最善でない手（玉のフラフラ等）を指していた | greedy選択(by_count=true)に修正、自己対局Eloと条件統一 |
| 4 | 1手1秒が未機能 | think_time_limitは打ち切り専用で、num_simulation=64が先に達し0.1秒で指了 | num_simulationの上限を上げ、時間制限が探索を止めるように |

これらは**評価パイプラインのバグ**であって、C++の学習・自己対局Eloには影響しない
（学習はaction_idとテンソルで動き、座標変換や着手選択の評価設定を経由しない）。

## 検討したバグ仮説と、それぞれへの反論（証拠）

各「まだバグでは?」に対し、証拠で否定した。

- **仮説A: 座標/盤面が壊れている**
  → 反論: 修正後の棋譜は完全に合法で、取り返し(`8g8f`→取り返し)・受け・駒打ちが
  局面に正しく対応。駒のワープや非合法手なし。**盤面は同期している**。

- **仮説B: restnetが詰みで異常に早く終わる**
  → 反論: 短さの主因は `actor_resign_threshold=-0.9` による**投了**（詰みではない）。
  投了を無効化(-1.1)すると手数は27〜30手に伸び、restnetは受けを継続した。
  「早い終局」は投了であり異常ではない。

- **仮説C: 時間制御が効かず64シミュレーションしかしていない**
  → 反論: 初期局面でのgenmoveの root node info が **count = 777**（1秒で777回）。
  学習時の64回を大きく上回り、時間制御は正常に機能。

- **仮説D: Gumbel探索が時間打ち切りで中断され、弱い手を選ぶ**
  → 反論: 777シミュレーションは sequential halving が十分機能する回数。選んだ手
  action 10535 = `4i3h`（標準的な金上がり）を方策76.6%の自信で選択。破綻なし。

- **仮説E: restnetが意味不明な手を指している（実力ではなく故障）**
  → 反論: greedy修正後の棋譜は将棋として筋が通る。例えば game0 では飛車先を
  伸ばして交換し竜で攻める、といった一貫した指し回し。負けたのは
  「8八の角を取り返さない」等の**局面理解の緩手**を咎められたためで、
  合法かつ理解可能な弱さ（＝棋力の問題）。

## 決定的証拠（初期局面でのgenmove、投了/サンプリング無効・greedy・1秒）

```
root node info: v = -0.0038, count = 777.0000
選択手: action 10535 = 4i3h（先手の金 4九→3八）, policy p = 0.7662
Spent Time = 1.001 (s)
```

- count=777 → 思考量は健全（過小評価されていない）
- v≈0 → 初期局面をほぼ互角と評価（価値ネットは正常）
- 4i3h → 標準的で合法な手を高い自信で選択

これで「思考が壊れている/評価設定で損している」可能性はすべて排除され、
**残るのは実力差のみ**と確定した。

## なぜ弱いのか（計算資源の観点、想定内）

| | AlphaZero(将棋) | 本restnet(将棋) |
|---|---|---|
| 自己対戦局数 | 約2400万 | 約60万（2.5%） |
| ネット | 20ブロック256ch | 6ブロック256ch（R_R_T_R_R_T） |
| 探索(学習) | 800 sims | 64 sims |
| 計算資源 | 約5000 TPU | 1 GPU |

ResTNet論文・MiniZero論文はそもそも将棋を扱っておらず（囲碁/Hex/オセロ）、
将棋への適用は本研究独自。トップエンジンにフル強度で勝てないのは当然で、
論文も弱いモデルを「参照相手への勝率」で報告している（人間段位は主張しない）。
