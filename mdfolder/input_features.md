# 入力特徴量とチャンネル（2026-09-24 作成）

ネットワークに何をどう渡しているか。チャンネルの数え方、計算される場所、使われる場所、
履歴が8時点である理由をまとめる。数値はすべてビルド済みバイナリで実測した。

## 1. チャンネルとは

入力は「盤と同じ大きさの面」を何枚も重ねたもの。**1チャンネル = 1面 = 特徴量1種類**。

```
9x9将棋   362チャンネル × 81マス = 29,322個の数値
5五将棋   266チャンネル × 25マス =  6,650個の数値
動物将棋  146チャンネル × 12マス =  1,752個の数値
```

面には2種類ある。

| 種類 | 値の入り方 | 例 |
|---|---|---|
| マス単位 | 該当する升だけ1、他は0 | 自分の歩、相手の玉 |
| 盤面全体 | 全マスが同じ値 | 持ち駒の枚数、手番、手数、千日手 |

持ち駒は升の情報ではないので、盤全体を同じ数で埋める。歩2枚なら全マスが2になる。
畳み込み層は面しか受け取れないため、数値1個の情報もこの形にする。

### 実測例（5五将棋）

先手玉5e、先手飛3e、後手玉3a、先手の持ち駒が歩2枚という局面。
1つの升について、266面のうち値が0でない面を並べたもの。

| 升 | 値が0でない面 |
|---|---|
| 玉のいる升 5e | 自分の玉=1、千日手1回目=1、自分の持ち駒:歩=2、手番=1 |
| 飛のいる升 3e | 自分の飛=1、千日手1回目=1、自分の持ち駒:歩=2、手番=1 |
| 何もない升 3c | 千日手1回目=1、自分の持ち駒:歩=2、手番=1 |

**駒の面は20枚あるが、1つの升で1になるのは多くても1枚。** 升に置ける駒は1個だから。
何もない升は駒の面が20枚とも0。持ち駒・手番・千日手はどの升でも同じ値。
値を足し合わせることはない。

**升の番号は盤の見た目と筋が左右逆。** 5eは番号24、3eは22。
9x9将棋が「1筋を0番」としているのに合わせてある（`shogi.cpp:373-382`、実測で確認）。

## 2. 各ゲームの内訳

### 9x9将棋 362

`shogi.cpp:353-357` に `num_channels = 362`、`T = 8`、`channels_per_step = 45`。

| 1時点あたり | 数 | 面番号 |
|---|---|---|
| 自分の駒 14種 | 14 | 0–13 |
| 相手の駒 14種 | 14 | 14–27 |
| 千日手（1,2,3回目） | 3 | 28–30 |
| 自分の持ち駒 7種 | 7 | 31–37 |
| 相手の持ち駒 7種 | 7 | 38–44 |
| **小計** | **45** | |

45 × 8時点 = 360、＋手番1枚（面360）＋手数1枚（面361）＝ **362**。

AlphaZero 論文の将棋の入力と同じ（[experiment_plan.md](experiment_plan.md) の照合表）。

### 5五将棋 266

| 1時点あたり | 数 | 面番号 |
|---|---|---|
| 自分の駒 10種 | 10 | 0–9 |
| 相手の駒 10種 | 10 | 10–19 |
| 千日手（1,2,3回目） | 3 | 20–22 |
| 自分の持ち駒 5種 | 5 | 23–27 |
| 相手の持ち駒 5種 | 5 | 28–32 |
| **小計** | **33** | |

33 × 8 + 2 = **266**。手番は面264、手数は面265。

駒と持ち駒の並び順は9x9と同じであることを実測で確認した。


### 動物将棋 146

| 1時点あたり | 数 | 面番号 |
|---|---|---|
| 自分の駒 5種 | 5 | 0–4 |
| 相手の駒 5種 | 5 | 5–9 |
| 千日手（1,2回目） | 2 | 10–11 |
| 自分の持ち駒 3種 | 3 | 12–14 |
| 相手の持ち駒 3種 | 3 | 15–17 |
| **小計** | **18** | |

18 × 8 + 2 = **146**。手番は面144、手数は面145。

千日手の面が**2枚**なのは、3回目で終局するため。9x9将棋と5五将棋は4回目で終局するので3枚。

2026-09-24 まで動物将棋は18チャンネル・履歴なし・千日手の面なし・盤の回転なしだった。
同一局面3回で引き分けなのにネットワークには何回目かが見えず、同じ入力に違う正解が付いていた。
実測では学習に使う局面の2%、対局の28%が該当した。将棋family に揃えて解消した
（それ以前に学習した11構成のモデルは読み込めない）。

## 3. なぜ 2 を足すのか

手番と手数は**時点に依存しない情報**だから、履歴8回分を持つ必要がない。

- 手番は「今どちらの番か」。1手前の手番は、今の手番から分かる
- 手数は「今が何手目か」。1手前が何手目かも、今から分かる

だから45 × 8 のあとに1枚ずつ足す。一方、駒の配置や持ち駒や千日手の回数は時点ごとに
違うので、8回分を並べる。

手番が1枚で足りるのは0と1で表せるため。手数も数値1個なので1枚。
手数は 手数 ÷ 512 を全マスに敷く（`shogi.cpp:448`）。5五将棋も動物将棋も同じ512を使う。

## 4. チャンネル数はどこで決まり、どこで使われるか

### 決まる場所

各ゲームの環境クラスが返す。ここが唯一の定義。

```cpp
// minizero/environment/shogi/shogi.h:311
inline int getNumInputChannels() const override { return 362; }

// minizero/environment/minishogi/minishogi.h
inline int getNumInputChannels() const override { return kMinishogiNumInputChannels; } // 266

// minizero/environment/dobutsu/dobutsu.h
inline int getNumInputChannels() const override { return kDobutsuNumInputChannels; } // 146
```

### Python（学習側）へ渡る経路

```
環境 getNumInputChannels()
   ↓ restnet/learner/pybind.cpp:53
restnet_py.get_nn_num_input_channels()
   ↓ restnet/learner/train.py:27   バッチ用のメモリを確保
   ↓ restnet/learner/train.py:104  読み込んだ数値を (バッチ, チャンネル, 縦, 横) に整形
   ↓ restnet/learner/train.py:176  ネットワークを組み立てるときの入力チャンネル数
AlphaZeroNetwork の最初の畳み込み層
```

### C++（自己対局側）へ渡る経路

```
環境 getFeatures()              面の中身を作る
   ↓
minizero/network/alphazero_network.h:50  長さが チャンネル×縦×横 と一致するか検査
   ↓ 同:59                                (1, チャンネル, 縦, 横) の形にして
ネットワークに入力
```

学習済みモデル（`.pt`）にもチャンネル数が埋め込まれ、読み込み時に取り出される。

```
restnet/learner/network/alphazero_network.py:128  get_num_input_channels()
   ↓
minizero/network/network.cpp:30                   モデルから読み出す
   ↓
minizero/network/network.cpp:48                   起動時のログに出力
```

**つまり環境の1箇所を変えれば、学習側も自己対局側も自動で追従する。**
ただし既存の学習済みモデルとは形が合わなくなるので、再学習が必要になる。

## 5. なぜ履歴が8時点なのか

**AlphaZero 論文が将棋・チェス・囲碁すべてで T = 8 としているため。** それに合わせた。

論文が履歴を持つ理由として挙げているのは、繰り返しの検出。千日手や劫のように、
同じ盤面でも過去の経緯で扱いが変わる規則があるため。

**8という数そのものに根拠があるわけではない。** 論文はこの値を比較実験で選んだとは
書いていない。我々も8が最適だと確かめたわけではなく、9x9将棋に合わせている。

なお千日手の面（回数そのもの）は履歴とは別に持っている。繰り返しの判定に必要な情報は
この面が直接与えるので、履歴が無くても千日手だけは表現できる。3ゲームとも両方を持つ。
