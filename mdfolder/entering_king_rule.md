# 入玉と宣言勝ちルールについて（AZ論文との差分整理）

（2026-07-20 作成。27点法判定を削除し「上限=引き分け」に変更した際の検討記録）

## 2つの別概念を区別する

- **入玉点数勝ち（宣言法）**: 点数が足りる側が入玉条件を満たして「勝ち」を得る正規ルール
- **入玉引き分け逃げ**: 宣言法が**ない**環境で、負けている側が玉を敵陣に逃がし
  「詰み不可能 → 上限到達 → 引き分け(z=0)」を確定させる行動。
  ルールの穴への正しい適応であり、モデルの欠陥ではない

## なぜ実際の将棋では「入玉逃げ得」が起きないか

実際の将棋には持将棋・宣言法（24点/27点ルール）が最初からあり、
**点数の足りない側は入玉しても結局負ける**ため。
「入玉すれば引き分けが保証される」状況はルール上存在しない。
入玉は負けの回避装置ではなく、点数が足りる見込みがある時だけ有効な
状況限定の技術（プロ実戦でも普通に出現する）。

## NoEnteringKing とは

YaneuraOu（Elmoの土台エンジン）のUSIオプション `EnteringKingRule` の設定値で、
「入玉宣言勝ちを無効にする」の意味。AZ論文では**評価対局のElmo側**に
設定されたものであり、AZの学習環境の話ではない。

## ルール比較表

| | 実際の将棋 | AZ論文(学習) | AZ論文(Elmo評価) | 本リポジトリ(旧) | 本リポジトリ(現在) |
|---|---|---|---|---|---|
| 上限手数 | なし(持将棋あり) | 512、超過=引分 | 通常対局 | 200、27点法判定 | 512、超過=引分 |
| 宣言/点数勝ち | あり | **なし** | なし(明示無効化) | 実質あり(27点法が代役) | **あり**(CSA宣言法) |
| 相入玉の帰結 | 点数勝敗/持将棋 | 引き分け | — | 27点法で勝敗 | 宣言成立=勝ち、不成立=上限引分 |

- AZ論文は学習・評価とも宣言法なしで一貫（相入玉引き分けの穴を容認）
- 旧実装の27点法判定は意図せず持将棋の代役だった。論文準拠化で削除した
  ことで穴が開いたため、宣言法を明示的に導入した（論文からの意図的逸脱）

## 実装（minizero側）

- `env_shogi_enable_declaration_win`（デフォルトtrue、cfg 1行でOFF可）
- 条件（CSA 27点宣言）: 指した側の玉が敵陣1〜3段目（後手は7〜9）、
  敵陣内に玉以外の自駒10枚以上、点数（敵陣内駒+持駒、飛角=5他=1）が
  先手28点/後手27点以上 → 即勝ち
- 「王手されていない」条件は合法手の定義（自玉を王手に晒す手は指せない）
  で自動的に満たされる
- 終局理由を SGF の `RR[...]` タグに記録:
  `mate / resign / stalemate / perpetual_check / sennichite / declaration / cap`
- `scripts/sgf_stats.sh` は RR タグから「宣言」列を分けて集計
  （タグのない旧SGFは手数ヒューリスティックにフォールバック）

## 運用方針

- 宣言法は「自己発動的」: 弱いモデルでは条件がまず成立せず無害、
  入玉局面が現れる強さになって初めて働く
- `sgf_stats.sh` の「宣言」列を監視。ずっと0%なら実害なし。
  上限到達ゲームで入玉が多発し始めたら、宣言法が穴を塞いでいる証拠
- AZ論文と厳密比較する実験では `env_shogi_enable_declaration_win=false`
