### 3.2 図 2 の a3 のライオンが青い問題（10-31〜11-01）

**きっかけ**：図 2（6T が勝ちを失った後手番の局面の value の IG）で、後手が取れば勝つ相手のライオン a3 が青（−1.45）だった。前回のミーティングでは「相手のライオンがいること自体が value を下げる」と説明していたが、それなら取れる局面ではいつも青になるはずである。

**わかったこと**：
- 無作為な 2,000 局面のうち相手のライオンを取れる 1,166 局面で、相手のライオンが青になる割合は、先手番で 2.5%、後手番で 84.3% だった。前回の説明は成り立たない。
- 原因：全部 0 の基準では、手番の平面（先手番・後手番の 2 枚）も 0 になる。これは学習に一度も現れない「どちらの手番でもない」入力で、手番と駒の組み合わせの効きが駒の値に入る（この仕組みは確かめていない）。動物将棋の入力は盤を手番側に回さないので、手番の差が大きく出る。
- 「駒だけ 0」（盤上の駒と持ち駒の平面だけを 0 にし、手番と回数の平面は残す）の基準では、46.5% と 53.7% で、手番による差はほぼ消えた。ただし、この基準での value は手番側から見て −0.95（先手番）、−0.85（後手番）で、中立ではない。
- 9×9 の将棋では盤を手番側に回すので、手番による符号の反転は起きていない（185 局面で、|IG| > 0.02 のマスで符号が違う割合 0.0%）。
- policy（手の確率）の IG では、基準による反転は起きていない。動物将棋で 2 割ほどのマスの符号が向きで違うのは、盤を回さずに入れるため、モデルが 2 つの向きで違う計算をしているからと考えられる。

**途中の経過**：一度は「設計の誤り」と考え、IG の基準を駒だけ 0 に変えた訂正版（論文・図・コード）を作った（11-01 06:08〜06:09 のコミット 625eccd、a7c6b72、7ee25af、fdca326）。その後、引用した論文を全文読んで判断を改め、同じ日に提出版の状態に戻した（e729e66、f0dd42d、17c65d3）。今の paper.tex と xai_app.py は提出版と同じである。駒だけ 0 の基準で作った図は gpw_paper/figs_pieces_removed/ に残してある。

**訂正版を出さない理由**（gpw_paper/IG_基準.md）：
1. 提出版に事実と違う記述がない。
2. 提出版の基準は、引用した IG の原論文（Sundararajan ら）の勧め「基準での予測がほぼ 0」に合う（基準での value は 6T で +0.058、9×9 の R3(RRT) で +0.040）。原論文も、実際には現れない入力（文章の全部 0 の埋め込み）を基準に使っている。
3. 駒だけ 0 に変えることは誤りを正すことではなく、別の基準への取り替えになる。「中立」と「手番によらない」の両方を満たす基準は、試した中にない。
4. 手番による違いは入力どうしの相互作用の話で、論文はその傾向を主張していない。
5. 9×9 の将棋では起きていない。

**読んだ論文**：
- Sundararajan ら（ICML 2017、論文の [5]）：IG は符号つきで読む。基準は「信号がない」入力。基準での出力がほぼ 0 か、合計が「出力 − 基準での出力」になるかを確かめる。ゲームや value の例はない。
- Czech ら（ECAI 2024、論文の [6]）：主な結果の基準は検証データの平均。付録の 2 局面では全部 0 を使い、理由は書いていない。論文では関連研究として紹介しただけで、基準の根拠としては引用していない。
- Kindermans ら（2017、引用していない）：IG の結果は基準で変わる。全部 0 の基準は入力の変換に対して不安定になりうる。
- Sturmfels ら（Distill 2020、11-10 に読んだ）：一定の基準（黒い画像など）では、基準と同じ値の特徴は x_i − x'_i = 0 なので重要度が 0 になる。最大距離・ぼかし・一様・ガウス・学習データの分布などの基準を比べ、どれが最良かの結論はないとしている。合計が「出力 − 基準での出力」になるかを、計算が収束したかの確かめに使う。

**発表で伝えること**：全部 0 の基準では、取れる局面で相手のライオンの符号が手番で反対になる傾向があった。同じ基準の厳密な Shapley 値でも起きるので（11-05 の比較、7.4 節）、IG の近似ではなく基準の選び方による。Attention Map の結果と、モデルの精度・強さは IG を使っていないので影響しない。

## 4. 動物将棋の環境の作り直しと再学習（次の論文のため。GPW では使わない）

### 4.1 理由

旧い動物将棋は MiniZero 本家の Breakthrough を写した作りで、盤を回さず、手番の平面が 2 枚、value は先手から見た値、行動の番号は盤の絶対座標だった。将棋・動物将棋の他の実装（9×9 の将棋、5五将棋、中屋敷・金子の AlphaZero の調査、Pgx）は、後手番で盤を回す。この違いが IG の手番による差と、向きによる一致率の差を生んでいた。

### 4.2 決めた設計（11-01）

参考にしたもの：AlphaZero の論文（Table S1）、中屋敷・金子「どうぶつしょうぎを用いた AlphaZero の手法の調査」（GPW 2019、18 平面、後手番は盤を反転、田中先生の完全解析で評価）、Pgx の animal_shogi（194 平面、8 局面の履歴）、MiniZero 本家の各ゲーム、lc0。

### 6.3 IG の基準と方法の比較（6T・RRTRRT・6R、gpw_paper/IG_基準.md）

相手のライオンを取れる局面とほかの局面を同じ数ずつ、4 つの向きで入れた（6T は 8,000 入力）。基準 3 つ（全部 0、駒だけ 0、データの平均）× 方法 4 つ（IG、同じ基準での厳密な Shapley 値、1 つの駒を除く、勾配 × 入力）。

- 全部 0 の基準で value が中立なのは 6T だけ（+0.058）。RRTRRT は −0.945、6R は −0.983。
- 取れる相手のライオンが負になる割合（先手番／後手番）：6T の全部 0 の IG で 2.9%／87.5%、同じ基準の Shapley 値で 10.0%／66.8%。3 つの構成すべてで、Shapley 値でも手番の差が出る。IG だけの性質ではない。
- 手番と回数の平面を残す基準（駒だけ 0）では、Shapley 値の差は 3 つとも小さくなる。ただし 6R の IG では差が残る。
- 手の確率の IG は、value より方法の間でよく一致する（最大の駒が同じ割合：全部 0 の IG と Shapley 値で 87%、value では 43%）。
- IG と Attention の上位 3 マスの重なりは、6T の第 5 T ブロックの第 4 ヘッドで 1.19、第 4 T ブロックの第 1 ヘッドで 1.31。IG の上位は駒のあるマスなので、偶然は「駒のあるマスから 3 つ選ぶ」1.30 と比べるべきで、それを超えない（10-22 のメモにあった「偶然 0.75 を上回る」は使わない。提出版の本文には入っていない）。

### 6.4 9×9 の SL のモデルの attention

9×9 には完全解析がないので、floodgate の棋譜で実際に指された手を仮の正解にした（test の 10%、39,654 局面）。

- 10T の第 9 T ブロックの第 3 ヘッドは、指された手と他の手で 0.803（取る手を除いて 0.744）。R3(RRT) の第 2 T ブロックの第 2 ヘッドは 0.785。位置のバイアスだけでは最高 0.55〜0.56。
- R3(RRT) の SL のモデルの重みは偏っている（第 2 T ブロックの第 2 ヘッドで、各マスからの最大の重み × 81 の平均が 10.2）。同じ局面・同じ測り方で、論文の自己対局の R3(RRT) は 12 ヘッドとも 1.001〜1.024 で、論文 4.3 節の「ほぼ均等」と合う。何が偏りを生んだか（データ、学習の量、強さ）はわからない。
- 偏ったヘッドほど、止めたときに policy の 1 位が指された手である割合が下がる（10T の 40 ヘッドで相関 0.80）。

1. **R3(RRT) と 10R の、SL から始める RL**（5.7 節）：R3(RRT) は実行中、10R はまだ（10T の RL は 11-11 に記録で確かめ、問題はなかった）。

4. 自己対局の worker の乱数の種は、学習ごとに同じ列になっている（11-10 に確かめた）。サーバーは自分の乱数を時刻で初期化するが、worker の種は通信の処理のスレッドで作り、乱数の生成器はスレッドごとに別なので、そのスレッドの生成器は既定の種のまま同じ列（1749605806、290934651、1945173367、1793167292、272702102、…）を出す。論文の 9×9 の R3(RRT) と 10R の Worker.log はこの順のとおりで、動物将棋の学習も 1749605806 だった。ただし、学習器の重みの初期値は実行ごとに違う（PyTorch の種は実行ごとに変わる。同じ構成 6T をゼロから 2 回始めた試運転と v2 の本番で、0 ステップ目の重み行列は、0 で始まる相対位置のバイアス 6 つを除いてすべて違った）。そのため学習は別のものになり、論文の結果には影響しない。同じ構成を乱数の種だけ変えて学習し直して比べるときは、worker の種を明示して変える必要がある。
5. lishogi の旧いデータ（data/bootstrap/sgf）は #11 の修正のあと作り直していない。今の SL では使っていない（SL を始めたコマンドは、記録ではすべて DATA=data/floodgate/sgf_2250 を付けていた）。ただし tools/quick-run.sh の pretrain は、DATA を付けないとこの旧いデータを読む。
