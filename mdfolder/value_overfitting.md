# value の過学習と最適な学習量（2026-08-30・調査中）

事前学習で **policy は伸び続けるのに value だけ途中から悪化する**。その理由と、どこで止めるべきかの記録。
結論はまだ出ていない。後で調べ直すための材料をまとめる。

## 1. 観測された事実

`shogi_9x9_v2`（lishogi 68,203局 = 6,443,538局面、batch 1024、lr 0.1、手番視点の value）。
`1 エポック = 6,293 ステップ`。

移動平均（±1,250ステップ）で均した推移。

| step | エポック | test_loss_value | test_accuracy_policy |
|---|---|---|---|
| 7,400 | 1.2 | 0.9209 | 0.4044 |
| 13,500 | 2.1 | 0.9057 | 0.4343 |
| **22,100** | **3.5** | **0.9023**（最良） | 0.4549 |
| 31,800 | 5.1 | 0.9041 | 0.4627 |
| 50,100 | 8.0 | 0.9285 | 0.4690 |
| 68,400 | 10.9 | 0.9704 | 0.4722 |
| 86,700 | 13.8 | 1.0019 | 0.4709 |

**value は 3.5 周で底を打ち、以降は悪化する。** 14 周時点の 1.0019 は
「何も学ばない場合の下限 0.996」を上回っており、未知の局面には無価値な状態。

一方 **policy は 14 周まで緩やかに改善し続ける**（0.404 → 0.471）。両者の最適点がずれている。

学習データ側は逆に下がり続ける（`loss_value` 0.715 @ 88,000）。典型的な暗記。

## 2. なぜ value だけ過学習するのか

### 独立したデータの数が桁違いに少ない

1局の全局面に**同じ勝敗ラベル**が貼られる。統計的には独立した94個のデータではなく、
「この対局は先手が勝った」という1つの事実の複製。

```
policy : 1手ごとに異なる正解    → 6,443,538 個が独立
value  : 1局につき正解は1つだけ →    68,203 個しか独立していない（94分の1）
```

情報量で見るとさらに開く。

```
policy : 6,443,538 × log2(11,259手) = 86.7 Mbit
value  :    68,203 × 1 bit          =  0.068 Mbit
                                      → 1,272 倍の差
```

### 局面が対局を一意に特定できてしまう

実測（学習データから4,000局を無作為抽出、先頭N手の並びで照合）。

| 一致範囲 | 種類数 | うち1局しかないもの |
|---|---|---|
| 10手目まで | 3,205 | 89.4% |
| 20手目まで | 3,929 | 99.3% |
| 30手目まで | 3,896 | 99.7% |
| 60手目まで | 3,436 | **100.0%** |

中盤以降の局面はその対局を完全に特定する。したがってネットワークは

```
「この局面を見たことがある → あの対局だ → 結果は先手勝ちだった」
```

という対応表を作るだけで学習データに満点を出せる。**盤面を評価する必要がない。**

## 3. 先行研究

### AlphaGo は明示的に報告している

> "successive positions are strongly correlated, differing by just one stone, but the regression target is
> shared for the entire game. When trained on the KGS dataset in this way, **the value network memorised the
> game outcomes rather than generalising to new positions**, achieving a minimum MSE of 0.37 on the test set,
> compared to 0.19 on the training set."

> "To mitigate this problem, a new self-play data-set consisting of **30 million distinct positions, each
> sampled from a separate game**, was generated. ... Training on this data-set led to MSEs of 0.226 and 0.234
> on the training and test set, indicating minimal overfitting."

学習0.19 / 検証0.37 という乖離は、今回の 0.715 / 0.997 と同じ構造。

**ただしこの対策は今回の構成には使えない。** AlphaGo は policy と value を**別のネットワーク**として学習しており、
policy は全局面、value は1局1局面と**サンプリングを分けられた**。
minizero / ResTNet は1つのネットワークが両方の出力を持つため、1局1局面にすると
policy の教師データも 68,203 個に激減して policy が壊れる。

### ResTNet は何もしていない

論文（4.1.2節・6.2節）を確認した結果、以下はすべて**記載なし**。

- 過学習・暗記・学習/検証の乖離への言及
- 100万局からの局面の取り方（全局面か1局1局面か）
- value の損失・精度・品質の評価
- AlphaGo のサンプリング手法への言及
- 正則化・データ拡張

報告されているのは勝率（10R 53.6% → R3(RRT) 60.9%）と循環パターンのMSEだけで、
**value の品質は評価対象になっていない。**

実装側にも緩和策はない。

```cpp
learner_use_per = false                   // 優先度付き経験再生は無効
learner_value_loss_scale = 1.0f           // value の重みは等倍（SL学習器はこの値を読んでいない）
getEnvIDAndPosition(Random::randInt() % getDataSize())   // 局面単位の一様サンプリング
```

## 4. 未解決の論点：ResTNet が 0.8 周なら、我々も1周で止めるべきか

ResTNet の 19×19 囲碁は **100万局を 150,000 ステップ = 0.8 周**しか回していない。
1周も見ていないので暗記する余地がそもそも無く、**対策したのではなく規模で回避していた**とも読める。

ここから「我々も1周程度で止めるのが最良では」という仮説が立つ。**しかし実測はこれを支持しない。**

| | エポック | test_loss_value |
|---|---|---|
| ResTNet 相当 | 0.8 | 0.9387 |
| 1周 | 1.0 | 0.9317 |
| **実測の最良** | **3.5** | **0.9023** |
| 8周 | 8.0 | 0.9285 |

1周時点（0.932）は最良点（0.902）より明確に悪い。**エポック数を論文に合わせるのは根拠にならない。**

考えられる理由:

- データ規模が違えば最適なエポック数も変わる。小さいデータほど多く周回しないと収束しない
- ResTNet の 0.8 周は「最適だから」ではなく「計算資源の都合でそこまでしか回さなかった」可能性がある
  （論文の理由は "to reduce the computational costs"）
- そもそも ResTNet は value の品質を測っていないので、0.8 周で value が学習できていたかは不明

**この論点は未決着。** 後で調べるべきこと:

- ResTNet の配布モデル（`restnet-models/10B-go-19-models/`）で value の汎化性能を実測する。
  囲碁の棋譜で「黒番の局面 / 白番の局面」に分けた符号一致率を測れば、
  視点の問題と過学習の両方を同時に確認できる（将棋で使った手法がそのまま使える）
- 0.8 周で value がどの程度学習できるのかは、局数を増やした実験と合わせて見る必要がある

## 5. この構成で取れる手段

| 手段 | policy への影響 | value への効果 | 状態 |
|---|---|---|---|
| **局数を増やす** | 良い（データ増） | 良い（独立データ増、周回数も減る） | 未実施 |
| 早期終了 | 精度が2ポイント落ちる | 現状の最良を確保 | step 22,000〜35,000 が該当 |
| `learner_value_loss_scale` を下げる | 影響なし | 過学習は遅れるが学習も遅れる | 未検証 |
| 1局1局面サンプリング | **policy が壊れる** | 有効 | 採用不可 |

**局数を増やすことだけが、policy と value の両方に有利。**

```
lishogi 閾値1500      約130,000局（1.9倍）→ 14周 が 7.4周 相当に
+ floodgate 158,397局 合計 約288,000局（4.2倍）→ 3.3周 相当に
```

どちらも生データが手元にあるので再ダウンロードは不要。
ただし floodgate はエンジンの棋譜なので、「人間の棋譜で事前学習した」という記述は使えなくなる。

## 6. 現時点で採用すべきチェックポイント

`weight_iter_25000` または `weight_iter_35000`（保存は5,000ステップ刻み）。

```
step 22,100（最良）  test_loss_value 0.9023  test_accuracy 45.5%
step 88,000（最終）  test_loss_value 1.0019  test_accuracy 47.1%
```

policy の精度は1.6ポイント落ちるが、**value が機能する状態を保てる**。
MCTS は末端局面の評価に value を使うため、value が無効だと探索が成立しない。
