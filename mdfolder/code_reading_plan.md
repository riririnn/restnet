# コードを理解するための計画（2026-11-11 作成）

研究の主体は自分である。そのために、研究の結果を決めるコードを自分の言葉で説明できるようにする。
この文書は「何を、どの順に読むか」と「どこまで AI に任せ、どこを自分で確かめるか」を決める。
読むときは、案内書 [code_reading_guide.md](code_reading_guide.md) の章を順に使う。

## 1. 目標

- 研究の数字を決めるコードについて、「何が入って、何が出るか」を自分の言葉で説明できる。
- AI が出した変更（差分）を読んで、何が変わり、どの学習やどの数字に効くかを言える。
- 学習の途中の記録を見て、おかしいことに気づける（例：引き分けの割合が増え続ける）。

コード全体を細かく覚える必要はない。下の優先度の高い所から読む。

## 3. AI に任せてよい所、自分で確かめる所

| 種類 | AI に書かせてよいか | 自分で必ずすること |
|---|---|---|
| 学習の正解・損失・ゲームの規則（結果を決めるコード） | 書かせてよい。ただし変更は 1 つずつ出させる | 差分を読み、何が変わるか、どの学習に効くかを自分で言えるまでコミットしない。確かめのテスト（例：scripts/shogi_env_check.py）の結果を見る |
| 分析の数え方（論文の数字を作るコード） | 書かせてよい | 何を分母・分子にするかの定義は自分で決める。数個の局面で、手で数えた答えと合うかを見る |
| 動かす道具、記録の読み取り、表やグラフ | 任せてよい | 出てきた数字が常識的かを見る（例：勝率が 0% や 100% ばかりでないか） |
| 何を主張するか、結論、先生への報告 | 任せない | 自分で考えて書く。AI の意見は比べる材料にとどめる |
| コミットと push | 任せない（今の決まり） | コミット文と差分を読む。わからない変更はコミットしない |

**11-02 の反省：** 投了の不具合を直したコミットは、夜中の 3 時に 10 個まとめて作られ、論文のモデルに効く修正だと記憶に残らなかった。学習の結果を変える修正は、1 つずつ、影響（どのモデル、どの数字）を確かめてからコミットする。

## 4. 学習中に毎回見ること（数分）

Training.log（自己対局の学習）で、次の 3 つを見る。案内書の 1.6 節に式がある。

- 結果が 0 の対局の割合（1 − 標準偏差² − 平均²）：本当の引き分けは少ないはず。増え続けたら疑う（論文の R3(RRT) では iteration 500 で 56%）。
- 平均手数：急に短くなる・長くなる、を見る。
- 学習率（op.log の lr）：予定どおりに変わっているか。
