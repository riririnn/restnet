## 2. 時間の求め方

**生成されたファイルの日時から求める。** 学習中にストップウォッチを回す必要はなく、
終わった後からでも、何か月後でも同じ値が出せる。

### 全体の所要時間

チェックポイントの最初と最後の更新時刻の差を取る。

```bash
ls -l --time-style=+%F_%T models/<ラン名>/model/weight_iter_0.pt
ls -lt --time-style=+%F_%T models/<ラン名>/model/*.pt | head -2
```

`weight_iter_0.pt` が学習開始、最後のものが終了にあたる。

### 1イテレーションあたりの時間

棋譜は1イテレーションにつき1つ作られるので、数と時間の差から割り出せる。

```bash
ls -lt --time-style=+%F_%T models/<ラン名>/sgf/*.sgf | tail -1   # 1.sgf、最初
ls -lt --time-style=+%F_%T models/<ラン名>/sgf/*.sgf | head -1   # 最後
ls models/<ラン名>/sgf/*.sgf | wc -l                             # イテレーション数
```

時間差をイテレーション数で割る。**最初の1〜2イテレーションは初期化を含むので、
そこを除いて測ると正確。**

### 注意

- 途中で止めて再開したランは、停止していた区間が時間差に混ざる。その場合はファイルの
  日時を並べて、間隔が飛んでいるところを除く。
- 1枚の GPU を専有しているので、実時間がそのまま GPU 時間になる。複数の学習を同時に
  走らせた場合は共有になるため、その旨を明記する。**動物将棋は1本ずつ順に回すので専有。**

### 行動空間：不成を生成しない（論文に書くべき仕様）

**角・飛・歩は、成れる場面で不成を生成しない。** 銀は常に生成し、香と桂は段に応じて
条件付きで生成する。`MoveGenerator.cpp:39` の `exceptNonEffectiveNonProm = true` による。

これは**主要な将棋ソフトと一致する**。意図的にそう選んだのではなく、Sunfish 由来の
手生成器がそうなっていた。確認した結果、変えないほうが成功例に近い。

| 実装 | 角・飛 | 歩 | 銀 | 香・桂 |
|---|---|---|---|---|
| dlshogi（Apery系） | 詰将棋探索時のみ | 詰将棋探索時のみ | 常に生成 | 条件付き |
| やねうら王 | 生成しない | 生成しない | 生成する | 条件付き |
| 本実装（Sunfish系） | 生成しない | 生成しない | 常に生成 | 条件付き |

やねうら王は、全局面で不成を生成すると**約R30弱くなる**と実測している
（1秒思考で451勝525敗、2秒で419勝519敗、4秒で422勝485敗）。Bonanza の頃から
知られた性質で、枝が増える損が不成を読める得を上回る。

**AlphaZero との関係。** 論文の将棋の行動空間は 9×9×139 = 11,259 で、64+2の通常手と
64+2の成る手、7の打つ手から成る。**不成の平面は存在する。** 本実装の
`kShogiPolicySize` も 11,259 で、表現は同一。ただし**論文は合法手の生成方法を書いて
いない**ので、AlphaZero が不成を探索していたかは不明。

**帰結。** 方策ネットワークは11,259次元を出力するが、角・飛・歩の不成に対応する成分は
学習中に一度も正解にならない。表現上は存在するのに選べない手がある。

**事前学習データへの影響。** 人間の棋譜を再生すると、不成が指された局はその手で
打ち切られる。`data/bootstrap/sgf/test.sgf` の400局で7局、**1.8%**。破損ではなく
切り捨てで、残った局面の教師信号は正しい。

### 将棋の実装と成功例との対応（2026-09-11 確認）

不成の件を調べた流れで、他の項目も突き合わせた。**入力と行動空間は AlphaZero と完全に
一致し、規則は AlphaZero より厳密で、dlshogi・やねうら王に近い。**

| 項目 | 本実装 | AlphaZero | 判定 |
|---|---|---|---|
| 入力平面 | 362 | 362 | 一致 |
| 　内訳 | 自駒14＋敵駒14＋千日手3＋持ち駒14＝45 を8履歴＝360、＋手番1＋手数1 | 同じ | 一致 |
| 行動空間 | 11,259 | 11,259（64+2 通常、64+2 成り、7 打つ） | 一致 |
| 引き分けの値 | 0 | 0 | 一致 |
| 手数上限 | 512手で引き分け | 上限超過は引き分け | 一致 |
| 不成の生成 | 角飛歩は生成しない | **記載なし** | 比較不能 |
| 千日手 | 同一局面4回で引き分け | **記載なし** | 本実装が厳密 |
| 連続王手の千日手 | 王手をかけ続けた側の負け | **記載なし** | 本実装が厳密 |
| 入玉宣言 | 27点法で実装 | **記載なし** | 本実装が厳密 |
| 打ち歩詰め | 禁止（`board.cpp:705`） | 記載なし | 本実装が厳密 |

AlphaZero の論文は将棋の規則について「上限手数を超えた対局は引き分けとする」としか
書いていない。千日手も入玉宣言も触れていない。**本実装はそれらを備えており、規則としては
より正確**で、dlshogi・やねうら王と同じ立場にある。

入玉宣言の実装（`shogi.cpp:240`）は27点法。玉が敵陣、玉を除き10枚以上が敵陣、
大駒5点・小駒1点（持ち駒を含む）で先手28点・後手27点以上。「王手されていないこと」は
明示的に見ていないが、直前に自分が合法手を指している以上、自動的に満たされる。

### 検証済みの項目（2026-09-11）

学習を始める前に、実装を測って確かめた。読んで確認しただけの項目と区別するため、
**何をどれだけ測ったか**を残す。

| 項目 | 方法 | 規模 | 結果 |
|---|---|---|---|
| 行動IDの符号化 | C++ の合法手を Python で復号・再符号化 | 1,891局面 145,993手 | 完全一致 |
| 特徴量 | 同一局面で C++ と Python のテンソルを比較 | 25局 2,423局面 | 完全一致（盤・持ち駒・手番・手数） |
| value の視点 | 学習と同じ経路で教師信号を手番別に集計 | 4,000局面 | 手番で符号が反転 |
| 打ち歩詰め | 歩を打つと詰みの局面を作る | 1局面 | `P*5b` 非合法、`G*5b` 合法 |
| 二歩 | 同じ筋に自分の歩がある局面 | 1局面 | 同筋は非合法、別筋は合法 |
| 行き所のない駒 | 歩香の1段目、桂の1〜2段目 | 5通り | すべて正しく非合法 |
| 千日手 | 同一局面を4回繰り返す | 12手 | 終局・引き分け（0） |
| 連続王手の千日手 | 王手を繰り返す | 12手 | 終局・**王手側の負け**（-1） |
| 入玉宣言 | 4条件を1つずつ外して比較 | 4局面 | 全条件充足時のみ勝ち（+1） |
| ネットワーク構造 | 学習中のモデルの重みを数える | `dobutsu_6R` | 残差6段。設定と一致 |
| 価値/方策ヘッド | 著者同梱の 9x9 囲碁設定と比較 | — | `P` と `TV` が一致 |

**特徴量の比較で1件直した。** Python 側の手数の平面が1手分大きかった。SFEN の手数欄は
初期局面を1と数えるが、`getFeatures()` は指された手数を使うので0になる。学習は C++ 側を
通るので学習データに影響はなく、ずれていたのは XAI と詰将棋の解析だけ。
`tsume_shogi.py` を C++ に合わせた。

**価値ヘッドについて。** 論文本文は方策ヘッドと価値ヘッドの構造を書いていないが、
著者がリポジトリに同梱した `configs/9x9_go/RRTRRT.cfg` が `nn_policy_type=P`,
`nn_value_type=TV`, `nn_embed_kernel_size=3` としている。本文より、実際に走らせた設定の
ほうが強い証拠と判断してこれに合わせた。**10R でも価値ヘッドには Attention が入る。**

**任意局面の設定。** 稀にしか現れない規則は対局を進めても再現できないので、
`env_py` に `set_from_sfen` を追加した（`pybind_env.cpp`）。**将棋のビルドでのみ公開する**
ようマクロで囲んである。他のゲームには `setFromSFEN` が無く、囲まないと
`known_bugs.md` #3 と同じ「全ゲームがビルド不可」を繰り返す。

## 6. 論文に書く際の注意

- **論文の値と、我々が決めた値を区別する。** 上の表の「出典」列がそれ。
- **逸脱は3つだけ。** 将棋の10ブロック、動物将棋という盤、リプレイバッファの大きさ。
- **所要時間は計算機の性能と不可分。** 「1. 使用した計算機」を必ず併記する。
- **推定値は推定と明記し、実測に置き換えたら更新する。** どちらか分からない数字を
  論文に書かない。
- 乱数種は `program_auto_seed=true` で毎回変わる。同一条件の再現には固定が要る。
