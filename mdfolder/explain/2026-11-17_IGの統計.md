## 私たちが行ったこと（Czech らとの違い）

- 平均するもの：value の IG を、入力の平面ごとに全マスで足した値。符号を保って局面で平均した（符号を保って平均する点は Czech らと同じ。マスを足す点は、Czech らが書いていないので比べられない）。
- 基準：全部 0 と、駒と持ち駒を 0 の 2 つ。Czech らの図 5 の基準（データの平均）は使っていない。理由は「2026-11-17_IGの2つ目の基準」。
- 区間：95% のブートストラップ信頼区間（パーセンタイル法、scripts/ig_statistics.py の bootstrap）。9×9 は対局を単位に、動物将棋は局面（4 つの向きを 1 組）を単位にリサンプリングした。区間は、「区間が 0 を含むか」の記述だけに使う。Czech らは区間を出していない。
- リサンプリングの回数：1,000 から始め、倍にしても区間の端が 0.0005 以上動かなくなるまで倍にした（explain の数は小数第 3 位まで出すので、小数第 3 位の 1 の半分）。表ごとの回数は 16,000〜512,000 で、ig_planes_*.txt の各表の resamples の行にある。v2 の手番の平面の行は別にリサンプリングしていて、回数は出力していない。倍にする決まりで止めても、小数第 3 位が決まるとは限らない。別のエージェントと panel が乱数の種を変えて 100,000 回で計算し直した区間とは、端が最大 0.0006〜0.0010 違った（別のエージェントと panel の計算で、私は計算し直していない）。
- 11-17 の朝までは、回数に理由のない上限 64,000 があった。32 の表（9×9 の 14 と v2 の 18）のうち 28 が 64,000 で止まっていた。上限を消して作り直すと、32 の表のうち 24 で 64,000 より多い回数が要った。古い表と新しい表の区間の端の違いは最大 0.0009 で、平均は変わらない（古い表の写しは /tmp/claude-1000/-home-rin-restnet/49ea850f-dbdd-40f1-a6d5-c8383149e121/scratchpad/planes_cap64000/。一時的な場所で、消えることがある）。
- 確かめ：平面ごとの値を全部足した値は、積分では「局面での value − 基準での value」に等しい（IG の完全性）。300 ステップの和では近似なので、平面ごとの値の和と「局面での value − 基準での value」の差の絶対値を、表ごとに平均と最大で出した。

### 前の 7 局面の値の読み方（大事）

- IG は、出力が数学的に依存しない入力には、いつも 0 を割り当てる（Sundararajan ら 2017 の Sensitivity(b)："If the function implemented by the deep network does not depend (mathematically) on some variable, then the attribution to that variable is always zero."、litcheck/1703.01365.txt の 224-227 行）。前の 7 局面の平面の IG が 0 でないので、モデルの value は前の 7 局面の平面の入力に依存する。
- ただし、IG の経路の上の入力は、実際の局面ではない。
- 前の局面の駒の平面は、今の局面の駒の平面とほとんど同じである（違うのは、間に指された数手の分だけ）。モデルが「前の局面にしかない情報（指された手）」を使っているかは、IG からはわからない。前の 7 局面を変えたときの value の変化は、測っていない。
- Czech らの「move history information are of limited importance」とは、基準もモデルも違うので、比べられない。

### 符号の読み方

- ある平面の IG は、基準から入力までまっすぐに入力を変えたときの、平面の分の value の変化である。
- 平面の平均の符号は、基準で変わる。例：6T の終わっていない局面の相手のきりんの平面の平均は、全部 0 の基準と駒と持ち駒を 0 の基準では負（−0.154 と −0.194）、データの平均の基準では正（+0.116、ig_planes_v2_6T.txt）である。ただし、データの平均の基準の +0.116 は、相手のきりんが盤上にない入力に付いた IG による（盤上にない入力の平均 +0.426 [+0.392, +0.461]、盤上にある入力の平均 −0.017 [−0.048, +0.014] で区間が 0 を含む。panel が見つけ、私が npy から計算し直した）。データの平均の基準では、駒がない入力にも IG が付くので、2 つの基準と同じ量を比べていない。
- ライオンは 2 つとも全入力で盤上にある。そのため、ライオンの平面の値は「ライオンがあるか」の違いを表さない（Czech らの king についての注意と同じ）。

基準での value は、表の 3 つの重みと 2 つの基準で約 −1（手番の側の負け）である。そのため、表の各列の和（＝value − 基準での value。完全性の差を除く）は、終わっていない局面では +1.050〜+1.123、取れる局面では +1.898〜+1.966 になる。
