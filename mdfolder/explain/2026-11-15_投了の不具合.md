## 3. 1:49 の説明をやり直す

### 3.1 誤り 1：policy の正解も変わる

私は「policy の正解（探索の訪問回数）は壊れていない」と書いた。誤りだった。
この学習の policy の正解は、訪問回数ではなく次の式で作る（`minizero/minizero/actor/gumbel_zero.cpp:35-55`）。

$$
s(a) = \mathrm{logit}(a) + \bigl(50 + \max_b N(b)\bigr) \times 1 \times Q(a)
$$

$$
\pi_{\text{正解}}(a) = \frac{\exp s(a)}{\sum_b \exp s(b)}
$$

- 50 と 1 は設定（cfg の `actor_gumbel_sigma_visit_c=50`、`actor_gumbel_sigma_scale_c=1`）。
- $Q(a)$ は value をそのまま使う。論文の設定は `actor_mcts_value_rescale=false` で、値の範囲を広げ直す処理はしない（`minizero/minizero/actor/mcts.cpp:40-53`）。

**係数の大きさ。** 1 手 64 回の探索で、候補を 16 手から 8、4、2 手と半分ずつに絞る（sequential halving。`gumbel_zero.cpp` の 99 行と 109-115 行）。最後まで残った手の訪問回数は 1＋2＋4＋8＝15 で、これが $\max N$ の最大（合法手が 16 以上のとき）。係数は $50 + 15 = 65$。

**例。** 2 つの手の logit が同じで、Q 値が 0.02 だけ違うとする。

| | 点数の差 $65 \times \Delta Q$ | 正解の確率 |
|---|---|---|
| value がそのまま（$\Delta Q = 0.02$） | 1.30 | 0.79 と 0.21 |
| value が 0.6 倍になった（$\Delta Q = 0.012$） | 0.78 | 0.69 と 0.31 |

value の絶対値が小さくなると Q 値の差も小さくなり、policy の正解はネットワーク自身の logit に近づく。
ただし、実際の学習で policy の正解がどれだけ変わったかは、測っていない。
（2026-11-15 に直した。前は係数を 114 と書いていたが、この設定では最大 65。）

**ほかにも value の大きさを使うところがある。** どれも、どれだけ効いたかは測っていない。
- 投了の判定（`minizero/minizero/actor/mcts.cpp:84-89`）：value が −0.9 を下回るかで決める。value の絶対値が小さくなると、投了は起きにくくなる。
- 自己対局で指す手の抽選（同 106-124 行）：最も訪問の多い手との value の差が 0.1 以内の手から選ぶ。value の絶対値が小さくなると差も小さくなり、選ばれる手が増える。

### 3.4 新しく分かったこと：第 2・第 3 T ブロックは 20,000 ステップ以降、学習されていない

**weight decay だけが働くと、重みはどうなるか。**
PyTorch の SGD（`restnet/learner/train.py:196-200`）は、毎ステップ次のように重み $w$ を更新する。$g$ は損失の勾配。

$$
v \leftarrow \mu v + (g + \lambda w), \qquad w \leftarrow w - \eta v
$$

勾配 $g$ がほぼ 0 なら、$v$ は $\lambda w / (1-\mu)$ に近づき、重みは毎ステップ同じ割合で小さくなる。

$$
w \leftarrow w \left(1 - \frac{\eta \lambda}{1-\mu}\right)
$$

これを $n$ ステップ繰り返すと、およそ次の倍になる。向きは変わらない（cos = 1）。

$$
\exp\!\left(-\frac{\lambda}{1-\mu}\sum_{\text{ステップ}} \eta\right)
$$

**代入する。** $\lambda = 0.0001$、$\mu = 0.9$ なので $\lambda/(1-\mu) = 0.001$。

- 20,000 → 60,000 ステップ：学習率はずっと 0.02。$\sum \eta = 40{,}000 \times 0.02 = 800$。$\exp(-0.8) = 0.449$。
- 60,000 → 100,000 ステップ：70,000 まで 0.02、90,000 まで 0.01、そのあと 0.005。$\sum \eta = 10{,}000 \times 0.02 + 20{,}000 \times 0.01 + 10{,}000 \times 0.005 = 450$。$\exp(-0.45) = 0.638$。

**測った値（query と key の重み）。**

| | 20k → 60k の大きさの比 | 60k → 100k の比 | 20k と 60k の cos |
|---|---|---|---|
| 勾配がないときの予測 | 0.449 | 0.638 | 1 |
| 第 2 T ブロック（第 7 ブロック） | 0.450 | 0.638 | 0.9997 |
| 第 3 T ブロック（第 10 ブロック） | 0.449 | 0.638 | 1.0000 |
| 第 1 T ブロック（第 4 ブロック） | 0.478〜0.483 | 0.656〜0.662 | 0.954〜0.961 |

第 2・第 3 T ブロックは予測と 3 桁目まで一致した。20,000 ステップ以降、query と key は weight decay で小さくなっただけで、損失の勾配をほとんど受けていない。
第 1 T ブロックだけは予測より大きく、向きも変わった。少し学習された。

**学習の最初から 20,000 ステップまでも、大きさは予測と合う。** query と key の重みは、標準偏差 0.02 の乱数で始まる（`restnet/learner/network/alphazero_network.py:110-113`）。256×256 の行列なので、大きさは約 $0.02 \times 256 = 5.12$。20,000 ステップまでの学習率は 0.02 なので、予測は $5.12 \times \exp(-20{,}000 \times 0.02 \times 0.001) = 5.12 \times 0.670 = 3.43$。測った 20,000 ステップの大きさは 3.429〜3.440 で、合う。
投了がまだ少なかった最初の時期（iteration 10 で 2,000 局のうち 20 局）から、query と key はほとんど学習されていなかった可能性が高い。
ただし、確かめられたのは大きさだけで、向き（cos）は最初の重みが手元にないので確かめられない。

## 4. 1:52 の説明をやり直す：value が本当の結果より 0 に近いこと

### 4.1 value が 0 に近いとは

value が、本当に出力すべき値より 0 に近い値（絶対値が小さい値）になっていること。「value が過小になっている」「較正がずれている」とも言える。

### 4.2 なぜ 0 に近くなるか（式）

value の損失は二乗誤差（`restnet/learner/train.py:279-284`）。

$$
L = \frac{1}{n}\sum_k \bigl(v_k - z_k\bigr)^2
$$

同じような局面に、正解 $z$ が +1 のものと 0 のものが混ざっていると、二乗誤差を最小にする $v$ は正解の平均になる。
勝ちの対局のうち割合 $p$ が投了で終わり、正解が 0 と記録されたとすると、

$$
v \approx (1-p) \times 1 + p \times 0 = 1 - p
$$

本当は +1 を出力すべき局面で、$1-p$ しか出力しなくなる。負けの局面も同じで、$-(1-p)$ になる。これで value が本当の結果より 0 に近くなる。
2 節の割合から予想すると、iteration 100 で $1-p \approx 0.68$ 倍、iteration 500 で $\approx 0.44$ 倍。
（どの局面が投了の対局に入るかは局面によるので、これはおおまかな予想。）

### 4.3 どう測ったか：傾き

論文の学習の棋譜（100・300・500.sgf）から、局面を 5% ずつ取った。投了した対局は、投了した側の負けとして本当の結果 $t$（+1 か −1）を直した。
モデルの value を $v$ として、$t \approx b \times v$ に一番よく合う $b$ を「傾き」とした（原点を通る最小二乗）。

$$
b = \frac{\sum_k v_k\, t_k}{\sum_k v_k^2}
$$

- $b = 1$：value の大きさが正しい。
- $b > 1$：value が本当の結果より 0 に近い（絶対値が小さい）。$1/b$ 倍になっている。
- $b < 1$：value が大きすぎる（絶対値が本当の結果より大きい）。

### 4.4 結果

| モデル（その時期の棋譜の局面で） | 傾き $b$ | 倍率 $1/b$ | 予想 $1-p$ |
|---|---|---|---|
| 論文 20,000 ステップ（iteration 100） | 1.57 | 0.64 | 0.68 |
| 論文 60,000 ステップ（iteration 300） | 1.68 | 0.60 | 0.56 |
| 論文 100,000 ステップ（iteration 500） | 1.70 | 0.59 | 0.44 |

value を区間に分けて、本当の結果の平均を見ても同じ（論文 100,000 ステップ、500.sgf の局面）。

| value の区間 | −1〜−0.5 | −0.5〜−0.2 | −0.2〜−0.05 | −0.05〜+0.05 | +0.05〜+0.2 | +0.2〜+0.5 | +0.5〜+1 |
|---|---|---|---|---|---|---|---|
| 本当の結果の平均 | −0.84 | −0.59 | −0.14 | +0.01 | +0.33 | +0.70 | +0.88 |

value が +0.2〜+0.5 の局面は、本当の結果の平均が +0.70。value は本当の結果より 0 に近い。

**投了の対局だけではない。** 終局の 20 手前までの局面で、$v \times t$ の平均は、投了の対局 0.34、詰み・入玉宣言の対局 0.36 でほぼ同じ。モデルは「投了で終わる対局」の局面でだけ 0 に近い値を出力するのではなく、投了の対局と詰みの対局で同じように 0 に近くなっている（最後の自己対局の局面での話）。

**どの局面で測るかで変わる。** 最後のモデル（100,000 ステップ）を古い棋譜の局面で測ると、傾きは iteration 100 の局面で 1.09、iteration 300 の局面で 1.37、iteration 500 の局面で 1.70。「約 0.6 倍」は、最後のモデルを最後の自己対局の局面で測った値である。プロの棋譜の局面（論文の図の局面）では測っていない。

**弱いところ。**
- 予想 $1-p$ は後半ほど小さくなるが、測った倍率 $1/b$ は 0.64 → 0.59 とあまり変わらない。理由は分からない。
- 比べる相手がいない。不具合のない SL のモデルと SL から始めた RL は、この局面で $b$ = 0.53〜0.73（value の絶対値が大きすぎる）だった。ただ、どちらもこの弱い自己対局の局面で学習していないので、比べる相手にならない。不具合のない自己対局のモデルを、自分の棋譜の局面で測れば比べられる（SL から始めた RL の 10T の棋譜が 1 つあれば測れる）。
