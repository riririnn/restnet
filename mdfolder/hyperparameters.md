# 主要ハイパーパラメータの違いまとめ（温度・割引率・学習率・ノイズα・ノイズε）

（2026-07-19 作成。AlphaZero論文準拠化の際の整理）

## 一覧表

| パラメータ | cfg名 | 効く場所 | 役割 | 論文の値 | 本リポジトリの値 |
|---|---|---|---|---|---|
| 温度 τ | `actor_select_action_softmax_temperature` | **着手選択**（探索の後） | 探索結果（訪問回数）からどう1手を選ぶか | 学習中は全手 τ=1、評価時のみ greedy | 1（cutoff=0、decay=false） |
| 割引率 γ | `actor_mcts_reward_discount` | **探索木のバックアップ** | 木の深さ方向に価値を減衰させる | 存在しない（γ=1） | 1 |
| 学習率 LR | `learner_learning_rate` | **ニューラルネットの重み更新** | 1回の勾配更新でどれだけ重みを動かすか | 0.2→0.02→0.002→0.0002（3回減衰） | 0.02 起点で同比率減衰（batch換算、curriculum_train.sh が 1/7・3/7・5/7 地点で自動適用） |
| ノイズ α | `actor_dirichlet_noise_alpha` | **探索の前**（ルートの事前確率） | 混ぜるノイズの「形状」（少数の手に集中 vs 均等） | 将棋 0.15 | 0.15 |
| ノイズ ε | `actor_dirichlet_noise_epsilon` | **探索の前**（ルートの事前確率） | ノイズを「何%混ぜるか」の混合比 | 0.25 | 0.25 |

## それぞれの違い（1手の流れに沿って）

1手を指すまでの処理順に並べると、各パラメータの守備範囲が重ならないことが分かる:

```
方策ネット出力 p
  → [α, ε] ルートの事前確率にノイズ混合  P' = (1-ε)p + ε·Dir(α)
  → [γ]    MCTS探索（バックアップ時に価値を深さ1段ごとに γ倍）
  → [τ]    訪問回数分布から着手を選択  P(a) ∝ N(a)^(1/τ)
  → ゲーム終了後
  → [LR]   (局面, π, z) を教師データにネットを更新
```

### 温度 τ — 「探索結果をどう使うか」
- τ=1: 訪問回数に**比例**して確率的に選ぶ（学習データの多様性を確保）
- τ→0 (greedy): 訪問回数**最大**の手を常に選ぶ（評価対局・実戦用）
- 注意: τ=1 の実質的なランダム性はシミュレーション数に依存する。
  800 sims では訪問が最善手に集中するので「ほぼ greedy + 揺らぎ」だが、
  64 sims + Gumbel では分布が平坦なため強いランダム化として働く。

### 割引率 γ — 「木の中の価値減衰」（本プロジェクトでは廃止）
- バックアップ時に `value ← reward + γ × value` を深さ1段ごとに適用
- ボードゲームは途中報酬が常に0なので、γ<1 は「Q値を深さ分だけ縮める」
  効果しかなく、学習ターゲット（ゲーム全体の z）には一切影響しない
- 0.99 にしていた時期があるが「速い勝ちを促す」効果はほぼなく、
  PUCT の探索/活用バランスを歪める副作用の方が大きいため 1 に戻した
- 速い決着への圧力は現在「上限到達 = 引き分け(z=0)」の終端報酬が担う

### 学習率 LR — 「ネットの更新幅」（探索とは無関係）
- 上の4つと違い、自己対戦ではなく**Optimization段階**のパラメータ
- 大きすぎると発散、小さすぎると収束が遅い。序盤は大きく→終盤は小さく
  が定石（論文は10分の1×3回）
- 論文の 0.2 は batch 4096 の値。バッチサイズに比例させて換算する:
  batch 512 → 0.2×512/4096 ≈ 0.025 ≈ 0.02（LR_BASE のデフォルト）
  batch 1536 → 0.075（bigserver では `LR_BASE=0.075` を指定）

### ノイズ α — 「ノイズの形状」
- Dir(α) からサンプルされる確率ベクトル η の尖り方を決める
- α小（0.15）: ランダムに選ばれた**少数の手だけ**が大きく持ち上がる
  → 方策ネットが無視している手も時々真剣に探索される（局所解からの脱出）
- α大: 全手に薄く均等 → どの手も探索する気になる量にならず効果が薄い
- 合法手数に反比例させる: チェス 0.3 / 将棋 0.15 / 囲碁 0.03

### ノイズ ε — 「ノイズの量」
- P' = (1-ε)·p + ε·η の混合比。0.25 = 方策75% : ノイズ25%
- α が「25%の中身がどんな形か」、ε が「そもそも何%混ぜるか」で役割が別
- 自己対戦のみ ON。評価対局では ε 相当を 0 に
  （`actor_use_dirichlet_noise=false`）

## 評価対局（shogi_eval.py）での指定

学習時とは違い、論文準拠の評価は greedy + ノイズなし:

```bash
python3 scripts/shogi_eval.py --model1 ... --model2 ... \
  --conf configs/9x9_shogi/RRTRRT.cfg --games 20 \
  --conf_str "actor_select_action_by_count=true:actor_select_action_by_softmax_count=false:actor_use_dirichlet_noise=false"
```
