## 1. 動物将棋：完全解析の全局面での一致率

### 方法：Haque・Wei・Müller（ACG 2021）と同じ定義

[On the Road to Perfection? Evaluating Leela Chess Zero Against Endgame Tablebases](https://icga.org/wp-content/uploads/2021/11/ACG_2021_paper_13.pdf) は、AlphaZero 型のチェス AI（Leela Chess Zero）を終盤の完全解析と照合した研究。その定義をそのまま使う。

| 項目 | 内容 |
|---|---|
| 局面 | 完全解析の全局面（246,803,167）。対称な局面は1つとして、完全解析のデータの向きで1回ずつ判定する |
| 対象 | 勝ちの局面のうち勝ちを失う手がある局面と、引き分けの局面のうち負けの手がある局面（どの手でも結果が同じ局面は除く） |
| 誤り | 勝敗を変えた手（勝ち→勝ちでない、引き分け→負け）。最短の手でなくても、勝敗を変えなければ正解 |
| 判定 | 探索なしで、方策が最大の合法手（先行研究の MCTS-0 にあたる） |
| モデル | 11構成の最終モデル（200 iteration） |

同じ計算で、局面の種類（勝ち・勝ちで手数0・引き分け・負け・負けで手数0）ごとの「最善手を選んだ割合」と、勝ちまでの手数ごとの誤り（先行研究の decision depth）も出る。

### 完全解析のデータについて確かめたこと

- 田中先生の GitHub：「初期局面から（相手のライオンを取れる時は必ず取るという条件で）到達可能な局面すべてを求め」た。
- 1つのデータは、元の局面・左右反転・180度回して先後を入れ替えた局面・その左右反転をまとめたもの（`dobutsu.h` の `normalize()`：「黒番に正規化した上で64ビット整数に変換し，flipしたものと小さい方を返す」）。左右対称の局面は1万局面中2つだけ。
- 手数0の勝ちは相手のライオンを取れる局面、手数0の負けは相手のライオンがトライ済みの局面（`makeWinLose.cc`）。

### 検証（全局面に進む前に通した）

| 確認 | 結果 |
|---|---|
| 最善手順の77局面で、入力・合法手・最善手を以前の方法と比べる | すべて一致。11構成の一致数も以前と同じ |
| 1手外れた4,222局面で同じ比較 | 合法手・最善手はすべて一致。入力は9局面で同一局面の出現回数の印だけが違った（以前は「2回目」、今回は「1回目」）。以前の入力で数えると11構成とも以前の値と一致 |
| 全局面の書き出しの件数 | 246,803,167（表と一致） |

全局面の結果ではない。データの向きだけで、上の定義で数えたもの。

## 2. 9×9：やねうら王との対局

### 論文で確認できた棋力の調節

| 方法 | 実績 |
|---|---|
| 探索ノード数の制限 | AobaZero（elmo を1手 251,000k ノード、Kristallweizen を1手 5500k ノードで比較）。[GitHub issue #54](https://github.com/kobanium/aobazero/issues/54) |
| 思考時間の制限 | AlphaZero（Elmo の1手40ミリ秒を基準に、思考時間による強さの変化を示した）。[arXiv 1712.01815](https://arxiv.org/pdf/1712.01815) |
| 強さの違う相手を複数 | ResTNet（KataGo の参照モデル4つ） |
| 対戦相手に Elmo | AlphaZero（2017年の世界コンピュータ将棋選手権の優勝プログラム） |

DepthLimit と駒得だけの評価関数は、実績が見つからなかった。やねうら王の手加減設定（Skill Level）は実装されていない（`#if STOCKFISH` の中だけ）。

### 順番（各設定で R3(RRT) と 10R を10局ずつ、先後均等、モデルは1手2秒）

1. Elmo を NodesLimit=1 で。両モデル全勝なら NodesLimit を 10, 100, … と増やす。
2. 水匠5 で同じように。
3. 1・2 で全敗なら、実績のない方法（DepthLimit=1、両方の制限、駒得だけの評価関数）。
4. それでも全敗なら、モデルの思考時間を延ばす。だめならランダム相手。
5. 両モデルの勝率が 0% と 100% の間に入った設定で本番。

以前の記録：水匠5 の NodesLimit 1〜1000 で 28局 1勝（どのモデルかの記録なし、1手2秒）。

サーバーにやねうら王を置き、手順1を実行する（ユーザーが開始）。

## 3. Attention Map：問題の局面の可視化

まず考えられる問題の局面をすべて図にし（論文と同じ表示と均等値基準を並べ、max を添える）、数字での比較は図を見てから決める。

| ゲーム | 問題の局面 | 出どころ |
|---|---|---|
| 動物将棋 | 勝ちの局面で負けの手を選んだ局面（ライオンを取らない局面を含む） | 1万局面の確認で記録済み（`data/dobutsu_lost_wins.csv`） |
| 動物将棋 | 最善手順で最善手を外した局面 | 最善手順の77局面 |
| 9×9 | 詰みのある局面（Deep Learning 系の将棋ソフトは詰みに弱いという報告） | 1手詰めのプリセット4問と、水匠5 が詰みを示した61局面 |
| 9×9 | 入玉の局面（AI は入玉が苦手という報告） | 手元の floodgate の棋譜から探す |
| 9×9 | モデルが悪手を指した局面 | やねうら王との棋譜28局を水匠5で解析する |

弱点の報告：[やねうら王の作者（2020）](https://yaneuraou.yaneu.com/2020/12/20/deep-learning-shogi-features/)、[やねうら王の作者（2024）](https://yaneuraou.yaneu.com/2024/02/05/shogi-ai-is-terrible-at-entering-king-shogi/)、[dlshogi の開発者（2024）](https://tadaoyamaoka.hatenablog.com/entry/2024/12/08/154055)。囲碁の循環パターンのような将棋 AI への攻撃の研究は見つからなかった。

## 4. 持ち駒の可視化（動物将棋で試作する案）

持ち駒はマスを持たず、全マスの入力に同じ値として入るので、Attention Map に持ち駒の場所はない。

| 案 | 内容 |
|---|---|
| (a) | 持ち駒を1枚減らした入力との、Attention の差を盤に描く |
| (b) | 最善手が駒打ちの局面で、打つ先のマスを起点にした Attention Map |
| (c) | 持ち駒の入力を消したときの、勝ちやすさと指す手の確率の変化 |
| (d) | 持ち駒の入力への勾配による寄与 |
| (e) | 持ち駒の種類ごとに、どのマスに打ちたいか（方策の駒打ちの確率）を盤に描く |
| (f) | 持ち駒を1枚増やした入力との、Attention の差 |
| (g) | 盤の横に駒台を描き、(c)・(d) の値で持ち駒に色を付けた図 |
