## 1. 動物将棋：完全解析の全局面での一致率

### 方法

| 項目 | 内容 |
|---|---|
| 局面 | 完全解析の全局面（246,803,167）を、先手番の向き（データの向き）と後手番の向き（180度回して先後を入れ替えた局面）でそれぞれ判定する（モデルは手番で入力が変わるため。下を参照） |
| 判定 | 探索なしで、方策が最大の合法手 |
| 指標 | 最善手を選んだ割合：選んだ手が完全解析の最善手（勝ちなら最短で勝つ手、負けなら最も長く粘る手）である局面の割合。GUI と同じ定義 |
| モデル | 11構成の最終モデル（200 iteration） |

### 完全解析のデータについて確かめたこと

- 田中先生の GitHub：「初期局面から（相手のライオンを取れる時は必ず取るという条件で）到達可能な局面すべてを求め」た。
- 1つのデータは、元の局面・左右反転・180度回して先後を入れ替えた局面・その左右反転をまとめたもの（`dobutsu.h` の `normalize()`：「黒番に正規化した上で64ビット整数に変換し，flipしたものと小さい方を返す」）。左右対称の局面は1万局面中2つだけ。
- 手数0の勝ちは相手のライオンを取れる局面、手数0の負けは相手のライオンがトライ済みの局面（`makeWinLose.cc`）。

| 1手外れた4,222局面で同じ比較 | 合法手・最善手はすべて一致。入力は9局面で同一局面の出現回数の印だけが違った（以前は「2回目」、今回は「1回目」）。以前の入力で数えると11構成とも以前の値と一致 |

- 同じ局面でも向きで結果が変わる。後手番の向きは、勝ちの局面で 0.02〜0.08 高く、負けの局面で 0〜0.05 低い（理由は未確認）。

**向きで結果が変わる理由として確かめたこと**

- 完全解析のデータは、すべて先手番の向きで保存されている（先頭20万局面で確認）。田中先生は後手番の局面を回して先手番と同じ局面として扱う（dobutsu.h の normalize()）。

- 9×9 の将棋とミニ将棋は後手番で盤を回す。AlphaZero と中屋敷・金子（GPW 2019）の動物将棋も回す。手番の印は MiniZero のどのゲームにもある。
- 盤を回して学習し直す案は、時間がないので見送った。

## 2. 9×9：外部エンジンとの対局

### 方法：出村・金子（GPW 2023）と同じ

[将棋81万（IPSJ 229354）](https://ipsj.ixsq.nii.ac.jp/records/229354) の 4.3 節を原文で確認した。

| 項目 | 出村・金子 | 本研究 |
|---|---|---|
| 相手 | 水匠5、1手1000ノード、置換表16MB、並列探索・定跡なし | 同じ（1000から下げても測った） |
| 開始局面 | 人間の棋譜集（shogi_depot）の9戦型、20〜40手目からランダム | 同じ棋譜集から作った（`scripts/make_openings.py`、各戦型2000局面、すべて合法手で確認） |
| 先後 | 記載なし | 各局面で先後を入れ替えて2局 |
| こちら | Gumbel、1手16シミュレーション | 16 と 64。ノイズなし、sequential halving で残った手 |
| 局数 | 各戦型2000局 | 試しは各条件90局 |
| 学習量 | 自己対局1000万局（Base は +214 Elo） | 100万局（ResTNet と同じ） |

論文の内容（原文で確認）：

- 目的：将棋の初期局面は1通りなので、AlphaZero 型の自己対局では序盤が似通う。駒の初期配置を入れ替えた 816,480 通りの初期局面（将棋81万）で学習し、いろいろな戦型に強くなるかを調べた。
- 学習：Gumbel AlphaZero、自己対局のみ（人間の棋譜は使わない）、1手16シミュレーション、どの条件も合計1000万局。16ブロックの Bottlenecked ResNet（128チャネル）、AdamW、学習率 0.001。千日手の棋譜は学習から除いた。
- 比べた環境：通常の初期局面だけ（Base）、将棋81万だけ、将棋81万で事前学習してから通常の初期局面、など5つ。
- 結果：水匠5（1000ノード）を ±0 として、Base は +214 Elo。将棋81万で事前学習すると、居飛車で約 +30、振り飛車・相振飛車で約 +50 Elo 上がった。
- 但し書き：「今回作成したプレイヤ側も水匠側も最高パフォーマンスの設定にはなっていない」。他のプログラムとの強さの比較ではなく、環境どうしの比較が目的のため。

相手をノード数で固定するのは、勝率が測れる強さにするためと、計算機によらず再現できるため。将棋の論文で相手と条件を同じにしたのは、AlphaZero 対 Elmo（同じ時間、AlphaZero が同等以上に強い）と MuZero 対 AlphaZero（同じシミュレーション数）だけだった（原文で確認）。

初期局面から始めないのは、両者とも決定的に指すため（同じ2局を繰り返すだけになる）。Science 版の AlphaZero も、将棋で人間の序盤の局面から始めた対局をしている。

### 結果（各90局、こちらの勝敗、引き分けなし）

| 水匠5 | 10R 16 | 10R 64 | R3(RRT) 16 | R3(RRT) 64 |
|---|---|---|---|---|
| 1000ノード | 4勝86敗 | 2勝88敗 | 0勝90敗 | 1勝89敗 |
| 500ノード | 6勝84敗 | 7勝83敗 | 1勝89敗 | 4勝86敗 |
| 300ノード | 7勝83敗 | 6勝84敗 | 4勝86敗 | 2勝88敗 |
| 100ノード | 1勝89敗 | 2勝88敗 | 5勝85敗 | 2勝88敗 |
| 1（下限、実際は約46ノード） | 0勝90敗 | 5勝85敗 | 2勝88敗 | 2勝88敗 |

- 相手を下限まで弱めても、勝率は 0〜8% のまま変わらない。水匠5は物差しに使えない。
- 100ノード・10R・16 の90局を再生して終わり方を数えた：こちらが詰まされた 76、詰んでいないのにこちらが投了 13、相手の投了 1。開始局面からの手数（両者合計）の中央値は39手。短い詰みを防げずに負けている。
- 直接対決 R3(RRT) 対 10R（ノイズなし、同じ開始局面、各90局）：16シミュレーションで R3(RRT) の 36勝54敗（40.0%）、64シミュレーションで 42勝3分45敗（48.3%）。以前の直接対決（1手2秒、Gumbel ノイズあり、初期局面、400局）では R3(RRT) が 60.6%。探索が少ないほど 10R に有利に見える（1手2秒の対局はノイズと開始局面も違うので、探索の量だけの効果とは言えない）。

## 4. 持ち駒の可視化

2つのゲームで同じ方法にした（案 (b) と (c)）。駒打ちの局面で、打つ先のマスを起点にした Attention Map と、持ち駒の寄与（手番側・相手の持ち駒の入力を1種類ずつ 0 にしたときの value と、その駒打ちの手の policy（確率）の下がり方）を並べる。持っていない駒の寄与は 0 になることを確かめた。例：E*a2 が最善手の局面で、手番側のゾウを 0 にすると E*a2 の確率が 0.51 下がった（6T）。

試作の案の一覧（10月18日に決めたもの）：

持ち駒はマスを持たず、全マスの入力に同じ値として入るので、Attention Map に持ち駒の場所はない。

| 案 | 内容 |
|---|---|
| (a) | 持ち駒を1枚減らした入力との、Attention の差を盤に描く |
| (b) | 最善手が駒打ちの局面で、打つ先のマスを起点にした Attention Map |
| (c) | 持ち駒の入力を消したときの、勝ちやすさと指す手の確率の変化 |
| (d) | 持ち駒の入力への勾配による寄与 |
| (e) | 持ち駒の種類ごとに、どのマスに打ちたいか（方策の駒打ちの確率）を盤に描く |
| (f) | 持ち駒を1枚増やした入力との、Attention の差 |
