## 1. 動物将棋：完全解析との一致率

### 指標（論文の手法の節を書き換え済み）

モデルの選択は、探索・ノイズ・抽選なしで、policy が最大の合法手とする。

| 指標 | 定義 |
|---|---|
| 最善手を選んだ割合 | 選んだ手が最善手（勝ちなら最短で勝つ手、負けなら最も長く粘る手）と同じ評価である局面の割合。最善手が複数あればどれでもよい |
| 勝ちの局面で勝ちの手を選んだ割合 | 手番側が勝ちの局面のうち、選んだ手の後も勝ちである局面の割合（手数は問わない） |

旧名「厳しい一致率」「勝ちを保った率」は使わない。

### 局面

- (a) 初期局面からの最善手順上の全局面（77局面）
- (b) 最善手順から1手外れ、以降は最善手順を最大12手たどった局面（重複を除く、約4,200局面）

### 局面数の内訳（手番 × 手番側から見た勝敗）

引き分けの局面は、どちらの集合にもなかった。

| (a) 最善手順 | 0 | 39 | 38 | 0 | 77 |
| (b) 1手外れ | 775 | 1,352 | 1,340 | 755 | 4,222 |

## 2. 動物将棋：Attention Map

### 決まったこと

| 項目 | 内容 |
|---|---|
| 作り方 | ResTNet 論文 §4.3・Fig. 5 と同じ。1つのブロックの1つのヘッドについて、起点のマスから各マスへの attention を、図ごとに [0, 1] に正規化して赤の濃淡で描く。起点は緑の点 |
| 局面 | 完全解析の最善手順の局面 |
| 起点のマス | **その局面の最善手で動かす駒のマス** |
| 妥当性の判定基準 | **起点のマスから、最善手の行き先のマスや、取る駒のマスに attention が向いているか** |
| 駒打ちの局面 | 最善手がすべて駒打ちの局面（77局面中16）は外す。駒を動かす最善手と駒打ちの最善手が両方ある局面（5局面）は、動かす手だけを使う。打つ先を起点にする扱いは、時間があれば後で検討する |
| 数値での判定 | **行き先への比** ＝ 起点のマスから行き先のマスへの重み ÷ 均等値 1/12 の、全判定手での平均。1 なら向いていない。動物将棋では駒を取る手も行き先のマスで取るので、この1マスで取る駒のマスも含む |
| 報告の範囲 | GUI で全構成・全ブロック・全ヘッドの表を出す。何を報告するかは先生と相談する（すべてを報告するのが第一候補） |

「最大かどうか」での判定は採らなかった。ほぼ均等なヘッドでも、1.01 倍と 1.00 倍の差で「最大」になるからである。

### 結果：行き先への比（最善手順の61局面、判定した手71個、11構成の最終モデル）

| 対象 | 行き先への比（平均） |
|---|---|
| 6T 第5層 ヘッド4 | 1.985（最小 0.519、最大 6.203） |
| 6T 第2層 ヘッド1 | 1.117 |
| 6T のそのほかの22ヘッド | 0.817〜1.049 |
| 6T 以外の9構成の全92ヘッド | 0.994〜1.006（1手ごとの値でも最大 1.031） |

- 行き先に均等より多く向いているのは、6T の第5層ヘッド4だけである（平均で約2倍）。
- 6T 以外の9構成は、行き先に対して均等と区別できない。
- 6T 第4層ヘッド1は、初期局面では b1 から a2 に 9.18 倍を向けている（下の表）。ただし平均では 0.817 で、行き先に向いているとは言えない。局面によって向き先が変わる。
- 全ヘッドの表は GUI の「最善手の行き先への Attention」の「計算する」ボタンで出る。

### 初期局面1つでの観察（参考）

`最大の比` ＝ そのヘッドの重み ÷ 均等値 1/12 の最大値。1 なら均等、12 なら1マスに集中。

| 構成・位置 | 最大の比 |
|---|---|
| 6T 第4層 ヘッド1 | 9.18（先手ライオン b1 から a2 へ） |
| 6T 第5層 ヘッド4 | 5.28 |
| 6T 第1層 ヘッド3、第2層 ヘッド1 | 1.62、1.56 |
| 6T のそのほかのヘッド | 1.43 以下 |
| 6T 以外の9構成 | 1.01〜1.03（ほぼ均等） |

### 注意点

論文と同じ [0, 1] の正規化をすると、ほぼ均等なヘッド（最大の比 1.01）にも濃い赤と薄い色がはっきり付く。図だけでは「構造がある」と誤って読まれるので、図に最大の比を添える。GUI では各図の題に表示している。

## 3. 9×9 の将棋：10R と R3(RRT)

### 結果

| 項目 | 値 |
|---|---|
| 対局数 | 400局（R3(RRT) の先手 200局・後手 200局） |
| R3(RRT) の成績 | 240勝 5分 155敗 |
| 得点率（引き分けは 0.5 勝） | 60.6% |
| 95%信頼区間（正規近似） | 55.8〜65.4% |
| 得点率 50% との差の z 値（標準偏差 0.5 で計算） | 4.25 |
| Elo 差 | +75 |
| 1手の時間 | 2秒（シミュレーション数の上限 8000） |

ResTNet 論文の 9×9 囲碁の RRTRRT（60.80%）と数字は近い。ただし、測り方が違う（論文は KataGo という共通の外部相手、本研究は 10R との直接対局）。「論文と同じ値が出た」とは書かない。

### 確認が必要な点：Gumbel ノイズ

論文の手法の節には「評価対局では Gumbel ノイズを用いず，訪問回数が最大の手を選ぶ」とある。一方、コードと設定を読むと次のようになる。

| 項目 | 既定の設定のとき | 根拠 |
|---|---|---|
| Gumbel ノイズ | 使われる（毎手、根の候補手に加えられる） | 両モデルの cfg が `actor_use_gumbel_noise=true`。`usi_bridge.py` の既定の conf_str はこれを切らない |
| 手の選び方 | Gumbel の sequential halving で最後に残った候補（ノイズ込みのスコアが最大の手） | `gumbel_zero.cpp:60-65` |

サーバーの対局ログには、実行時の conf_str が記録されていなかった。そのため、実際の設定は未確認である。対局を起動したコマンドが分かれば確定できる。

ノイズがあったこと自体は問題ではない（同じ棋譜の繰り返しを防ぐ）。直すのは論文の記述である。
